# hoptrace

Имплементация на `traceroute` на C++17 за Linux и Windows. Програмата показва всеки
рутер, през който минава пакет по пътя си до даден хост, и за колко време отговаря.

*English: [README.md](README.md)*

```console
$ hoptrace -n 10.0.3.2
Tracing route to 10.0.3.2 (10.0.3.2), 30 hops max, 3 probes per hop, 32 data bytes
 1  10.0.1.1  0.057 ms  0.009 ms  0.014 ms
 2  10.0.2.2  0.015 ms  0.008 ms  0.007 ms
 3  10.0.3.2  0.017 ms  0.008 ms  0.008 ms
Destination reached at hop 3.
```

## Възможности

- IPv4 и IPv6, имена на хостове или числови адреси.
- Изход на живо: всяка проба се отпечатва веднага щом пристигне отговорът ѝ.
- Имена на рутерите чрез обратен DNS или само адреси с `-n`.
- Под Linux ICMP пакетите се сглобяват и разчитат ръчно, включително контролната сума.
- Работи без root под Linux, когато системата позволява непривилегировани ICMP
  сокети, и без администраторски права под Windows.
- Спира по-рано, когато рутер съобщи, че целта е недостижима, и показва причината.
- Настройваеми първи хоп, максимален брой хопове, проби на хоп, време за изчакване
  и размер на данните.
- Без външни библиотеки.

## Бърз старт

Нужни са CMake 3.20 или по-нов и компилатор за C++17.

**Linux**

```sh
git clone https://github.com/alexDzhen/hoptrace.git
cd hoptrace
./scripts/build.sh
sudo ./build/hoptrace example.com
```

За инсталиране и работа без `sudo` след това:

```sh
./scripts/install.sh
hoptrace example.com
```

**Windows**

Инсталирайте Visual Studio 2022 с компонента "Desktop development with C++" и
изпълнете командите в "Developer PowerShell for VS 2022", където `cmake` е наличен.

```powershell
git clone https://github.com/alexDzhen/hoptrace.git
cd hoptrace
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
.\build\Release\hoptrace.exe example.com
```

Скриптовете изпълняват тези три команди:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

## Употреба

```text
hoptrace [опции] <хост>

  -m, --max-hops <n>     Отказва се след толкова хопа (по подразбиране 30)
  -f, --first-hop <n>    Започва от този хоп вместо от първия (по подразбиране 1)
  -q, --probes <n>       Проби към всеки хоп, 1-10 (по подразбиране 3)
  -w, --timeout <сек>    Секунди изчакване на всеки отговор (по подразбиране 2)
  -s, --size <байта>     Размер на данните в байтове (по подразбиране 32)
  -n, --numeric          Само адреси, без търсене на имена
  -4                     Само IPv4
  -6                     Само IPv6
  -h, --help             Показва помощ
  -V, --version          Показва версията
```

### Как се чете изходът

Всеки ред е един хоп: номер, адрес на рутера (и име, ако има) и времето за отиване
и връщане на всяка проба.

| Знак  | Значение                                                            |
|-------|---------------------------------------------------------------------|
| `*`   | Няма отговор в рамките на времето. Много рутери просто не отговарят. |
| `!H`  | Рутер съобщава, че хостът е недостижим                              |
| `!N`  | Рутер съобщава, че мрежата е недостижима                            |
| `!P`  | Недостижим протокол (IPv4) или порт (IPv6)                          |
| `!X`  | Комуникацията е административно забранена (защитна стена)           |

```console
$ hoptrace -n -q 2 10.9.9.9
Tracing route to 10.9.9.9 (10.9.9.9), 30 hops max, 2 probes per hop, 32 data bytes
 1  10.0.1.1  0.043 ms  0.005 ms
 2  10.0.2.2  0.010 ms !H  0.005 ms !H
Destination unreachable, reported at hop 2.
```

| Код на изход | Значение                                              |
|--------------|-------------------------------------------------------|
| 0            | Целта е достигната                                    |
| 1            | Целта не е достигната                                 |
| 2            | Грешни аргументи, непознат хост или липса на права    |

## Права под Linux

За изпращане на ICMP е нужен специален сокет. `hoptrace` опитва два вида в този ред:

1. **Raw сокет**. Изисква root или capability `CAP_NET_RAW`.
2. **ICMP datagram сокет**. Не изисква права, но системата трябва да го разрешава
   чрез настройката `net.ipv4.ping_group_range`. Повечето съвременни дистрибуции
   го разрешават.

Достатъчно е едно от следните:

```sh
sudo hoptrace example.com                                   # като root
sudo setcap cap_net_raw+ep /usr/local/bin/hoptrace          # еднократно даване на capability
sudo sysctl -w net.ipv4.ping_group_range="0 2147483647"     # разрешаване на непривилегирован ICMP
```

`scripts/install.sh` прави второто автоматично. Под Windows не е нужно нищо.

## Как работи

### Идеята: пакетите нарочно "изтичат"

Всеки IP пакет носи поле TTL ("time to live", в IPv6 се нарича "hop limit"). Всеки
рутер, който препраща пакета, го намалява с единица. Рутер, който трябва да
препрати пакет с TTL, стигнал нула, го изхвърля и връща на подателя ICMP съобщение
"time exceeded". Това съобщение идва от адреса на самия рутер.

`hoptrace` използва това, за да накара всеки рутер по пътя да се представи:

```text
TTL=1   източник ──▶ рутер 1  ✗ изтекъл     рутер 1 отговаря "time exceeded"
TTL=2   източник ──▶ рутер 1 ──▶ рутер 2  ✗ изтекъл     рутер 2 отговаря
TTL=3   източник ──▶ рутер 1 ──▶ рутер 2 ──▶ цел     целта отговаря "echo reply"
```

Пробите са ICMP echo заявки, същите пакети, които изпраща `ping`. Алгоритъмът в
[`tracer.cpp`](src/tracer.cpp) е:

1. Започва се с TTL = 1.
2. Изпраща се проба с този TTL и се чака отговор или изтичане на времето. Това се
   повтаря за зададения брой проби.
3. Отговор "time exceeded" разкрива рутера на това разстояние.
4. Отговор "echo reply" означава, че пробата е стигнала целта: край.
5. Отговор "destination unreachable" означава, че пътят свършва тук: край.
6. Иначе TTL се увеличава с единица и се продължава от стъпка 2, до максимума.

### Съпоставяне на отговорите с пробите

Всяка проба има собствен пореден номер. ICMP съобщението за грешка съдържа началото
на пакета, който го е предизвикал, заедно с IP заглавието, така че идентификаторът
и поредният номер на оригиналната проба се прочитат от това копие
([`icmp.cpp`](src/icmp.cpp)). Закъснели отговори на по-стари проби носят стар номер
и се пренебрегват.

Времето се мери с монотонен часовник между изпращането на пробата и получаването
на отговора.

### Имплементации за Linux и Windows

Алгоритъмът работи с мрежата през един малък интерфейс,
[`IcmpClient`](include/icmp_client.hpp): изпраща една echo заявка с даден
TTL и връща един резултат. Има две имплементации.

| | Linux | Windows |
|---|---|---|
| Файл | [`src/linux/icmp_client_linux.cpp`](src/linux/icmp_client_linux.cpp) | [`src/windows/icmp_client_windows.cpp`](src/windows/icmp_client_windows.cpp) |
| Механизъм | Raw сокет или ICMP datagram сокет | IP Helper API (`IcmpSendEcho2`, `Icmp6SendEcho2`) |
| Кой сглобява пакета | `hoptrace` | Windows |
| TTL | Опция на сокета `IP_TTL` / `IPV6_UNICAST_HOPS` | `IP_OPTION_INFORMATION::Ttl` |
| Права | Root, `CAP_NET_RAW` или `ping_group_range` | Не са нужни |

Windows разрешава raw сокети само на администратори, а защитната му стена спира
входящите ICMP съобщения "time exceeded", освен ако има изрично правило. IP Helper
API няма тези проблеми и затова системният `tracert.exe` също го използва.

Тъй като алгоритъмът зависи само от интерфейса, модулните тестове заменят мрежата
със симулация по сценарий и проверяват алгоритъма хоп по хоп.

### Какво показва и какво не показва трасирането

- Рутерите могат да не отговарят на изтекли пакети или да ограничават броя на
  отговорите си, така че `* * *` не означава прекъснат път.
- Маршрутът може да се смени между пробите, а при балансиране на натоварването
  проби към един и същ хоп могат да минат през различни рутери. Тогава на един ред
  има повече от един адрес.
- Времената включват и забавянето на рутера при създаване на отговора, затова
  междинен хоп може да изглежда по-бавен от целта.

## Тестове

Тестовете използват [doctest](https://github.com/doctest/doctest), включен в
`third_party/`, така че при компилация не се тегли нищо.

- Модулни тестове на алгоритъма срещу симулирана мрежа: нормални пътища, мълчаливи
  рутери, недостижими цели, лимит на хоповете, прекъсване и грешки при изпращане.
- Модулни тестове за контролната сума, сглобяването и разчитането на пакети,
  отпечатването на хоповете и командния ред.
- Тестове, които стартират самата програма.
- Тест, който трасира `127.0.0.1`. Пропуска се, ако системата не разрешава ICMP
  сокети за текущия потребител.

```sh
ctest --test-dir build -C Release --output-on-failure
```
